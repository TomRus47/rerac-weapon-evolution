# Weapon Evolution 0.3.2

Unofficial mod for **ReRAC 0.3.4-alpha**. Gameplay patch **0.1.6.50**,
configuration capability **48**, launcher **0.10.0**.

## Fixes and changes

- Fix R.Y.N.O. shotgun pellets that can stop in mid-air and retain dynamic object slots after reaching their range.
- Reserve the complete 7-column, 5-row volley before spending ammunition. If there is insufficient object capacity, wait and retry without charging ammo or emitting a partial volley.
- Keep newborn shotgun projectile heads alive on their first frame, before the next moby-anchor update.
- Prioritize every shotgun projectile head before optional trails and limit optional tail allocations under particle pressure, preventing early rows from consuming the full shared visual budget.
- Give experimental pellets their own update entry even when a planet's native Blaster-shot update entry is absent.
- Reduce repeated overlay recognition during planet loading; prepare shared menu/map tables before the loader reports ready, instead of repeating the work on the first playable frame.
- Share immutable overlay section storage and release temporary instruction indexes after preparation.
- Include the previous respawn, weapon, camera, UI and experimental-mode fixes.

The approved default INI, damage/XP balance and custom launcher icon are unchanged.
Existing personal INIs, presets and saves remain compatible. Audio diagnostics stay disabled.

## Installation and update

Extract the **complete player ZIP** and run `ReRAC_Weapon_Evolution.exe`.
Select your extracted ReRAC game data if automatic discovery does not find it.
Players do not need Python, Rust or earlier patch ZIPs. Use the included modded
`runtime/rerac.exe`; a vanilla runtime does not implement these fixes.

For an existing player folder, back it up, close the game and launcher, and copy
its personal `weapons.ini`, presets and launcher settings into the new package.
If copied settings remember an old absolute runtime path, select this new package's `runtime/rerac.exe` in the launcher. Do not replace the new package's runtime with the old one. Save data uses the
same locations as before. The fresh ZIP contains the approved default INI.

## Validation scope

Disc-free regression fixtures cover resource exhaustion, allocation rollback,
pellet lifetime/range expiry and recognition equivalence/cache lifetime.
The loading microbenchmark measures repeated code recognition, **not whole
planet load time**. Windows build results and exact package identities are in
`release-build.json` and the repository verification notes.

Keep this release a **draft** until in-game checks confirm repeated shotgun
firing, planet transitions/respawns and the reported first-frame stutter.
GPU uploads/shader compilation and other base-runtime loading costs remain.
